# Contributing to Full-Stack Tutorials

First off, thank you for considering contributing to this project! It's people like you who make the open-source community such an amazing place to learn, inspire, and create.

## How Can I Contribute?

### Reporting Bugs
If you find a bug, please open an issue and include:
- A clear description of the problem.
- Steps to reproduce the issue.
- Any relevant logs or screenshots.

### Suggesting Enhancements
We are always looking for new tutorials or better ways to explain concepts. If you have an idea, please open an issue to discuss it!

### Pull Requests
1. **Fork the repository** and create your branch from `main`.
2. **Implement your changes**. If you are adding a new tutorial, follow the established structure:
   - `Task.md`: Instructions.
   - `Tutorial.md`: Theoretical background.
   - `Step-by-Step-Guide.md`: Implementation walkthrough.
   - `Answer/`: Completed solution.
   - Root file: Boilerplate (e.g., `.js`, `.sql`, `.html`) with TODO comments for the student to complete.
3. **Test your code** to ensure it works as expected.
4. **Submit a pull request** with a clear description of what you've done.

## Style Guide
- Use clear, simple language in markdown files.
- Follow existing code patterns and indentation.
- Ensure all code is well-commented, especially TODOs in boilerplate files.

## Code of Conduct
Please note that this project is released with a [Contributor Code of Conduct](CODE_OF_CONDUCT.md). By participating in this project you agree to abide by its terms.

Thank you for your contributions!
